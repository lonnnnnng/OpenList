# UC 网盘 HLS 播放与 STRM 配置

UC 接入使用网页 Cookie 读取目录，并通过 UC 的云端转码接口播放视频。OpenList 代理 HLS 清单和分片，负责附加并刷新播放鉴权；播放器和 Emby 不需要保存 UC Cookie。

## 页面配置

在「管理 → 存储」选择 **UC**，挂载路径可设为 `/uc`，根目录 ID 为 `0`。

登录 `drive.uc.cn`，在浏览器开发者工具的「网络」面板找到 `pc-api.uc.cn` 的 `/1/clouddrive/file/sort` 请求，复制完整的 **Cookie 请求头值**。如果抓包显示多条 Cookie 请求头，使用分号和空格连接后填入同一个输入框。

开启「使用转码地址」，「转码清晰度」选择「自动（最高可用画质）」。也可以选择固定清晰度；账号没有该清晰度权限时会报错，不会静默返回其他视频。页面已经隐藏 UC 不使用的「移动端请求 URL」字段。

用户只维护这一份登录 Cookie，无需填写播放 URL、移动端 URL 或 `Video-Auth`。播放时服务端从 `/file/v2/play` 获取临时鉴权，并合并完整登录 Cookie。登录 Cookie 失效仍需重新登录、复制并保存；这与单次视频播放鉴权自动刷新是两回事。

## 播放方式和限制

- STRM 始终保存稳定的 OpenList `/d/...?...` 签名入口，使用局域网可访问的 `site_url`。
- OpenList 将该入口跳转到自己的 `/hls/.../index.m3u8`，再代理清单及分片。该 302 是站内跳转，不是客户端直连 UC CDN；视频流量会经过 OpenList 服务器。
- 清单中的相对地址、子清单、密钥和初始化分片均改写为 OpenList 地址。Cookie 保留在服务端，代理只允许同源 HTTPS 资源。
- 上游返回 401、403 或 412 时重新获取同一清晰度的播放鉴权，刷新清单后重试一次。分片地址在刷新前后保持稳定，已读取旧清单的播放器仍可继续请求。
- 临时播放会话保存在内存中，有效期为 12 小时，最多保留 128 个会话。服务器重启或会话到期后重新打开视频即可；STRM 无需重新生成。

当前账号实测可用 `high`（540×960）和 `low`（270×480），`super` 不可用。画质取决于账号权限、源文件和 UC 已生成的转码版本。

原文件 `/file/download` 接口虽返回 HTTP 206，但本次测试中两个不同源文件都返回同一段约 15 MB、60 秒的 UC 浏览器/会员提示视频，并非源文件。因此当前接入以「使用转码地址」为准，不能据此宣称原画下载或 UC CDN 无鉴权直连已经打通。

## 当前服务器的输出布局

| 用途 | 配置 |
| --- | --- |
| UC 挂载 | `/uc`，驱动 `UC`，云端转码、自动清晰度 |
| 媒体扫描 | `/uc/videos`，目录合并、自动深度 |
| STRM 输出 | `/uc/strm`，嵌套挂载 `Local` 存储 |
| 本地输出根目录 | `/home/lee/openlist/data/uc-strm` |
| STRM 镜像存储 | `/uc-strm`，来源 `/uc/strm` |
| Emby 媒体库 | `UC网盘` |
| Emby 扫描目录 | `/home/lee/ostrm/uc-strm/strm` |

`/uc/strm` 是本地输出挂载。扫描周期沿用全局 10 分钟设置，STRM 地址使用 `http://192.168.1.2:5244`。新增资源由定时扫描发现、生成本地 STRM 镜像，然后发送 Emby 增量通知。
