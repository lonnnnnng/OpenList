# 百度网盘 Cookie 播放与 STRM 配置

百度网盘新增网页 Cookie 登录方式，用于浏览文件、媒体扫描和播放。原有 OAuth 刷新令牌方式保留；没有 `auth_type` 的旧配置仍按 OAuth 处理。

## 页面配置

在「管理 → 存储」选择 **百度网盘 / BaiduNetdisk**，将「登录方式」设为「网页 Cookie（浏览与播放）」。

登录 `pan.baidu.com`，打开浏览器开发者工具的「网络」面板，进入网盘目录，找到 `/api/list` 请求，复制请求头中完整的 **Cookie 值**。填入「网页 Cookie」，根目录填 `/`。无需填写刷新令牌、网页请求 URL 或临时视频链接。

Cookie 模式下页面隐藏 OAuth、上传及旧下载接口设置；切换到 Cookie 时关闭「网页代理」，用于 302 播放。如需主动让服务器代理下载，可重新开启该选项。登录失效时重新复制 Cookie，编辑存储并保存。

当前 Cookie 模式仅实现浏览、下载地址解析和播放；上传、移动、重命名、复制、删除及容量查询均未接入。需要管理云盘文件时使用百度客户端，或继续使用已有 OAuth 模式。

## 地址解析

1. `/api/list` 按页获取文件，保留文件大小、ID、路径和目录信息。先完成分页，再按「仅列出视频文件」过滤；异常响应或重复分页会报错，避免把失败当作空目录。
2. `/api/filemetas` 获取指定文件的 `dlink`。路径使用 JSON 和表单编码，支持中文、空格、引号等字符。
3. 服务端携带登录 Cookie 请求第一层下载地址，只解析其返回的 CDN 跳转，不将 Cookie 转发到 CDN。
4. OpenList `/d/...` 返回最终 CDN 地址，播放器不需要百度 Cookie。链接最多缓存 5 分钟，存在可识别的绝对过期时间时提前失效。

文件信息请求必须包含 `logid`。实测缺失时，元数据接口虽返回成功，得到的下载链接却返回 403 / 31362。该字段由服务端为每个请求生成，不需要用户维护。

STRM 中保持稳定的 OpenList 地址：`{site_url}/d{path}?sign={sign}`。不要写入会失效的百度 CDN URL。

## 当前服务器的输出布局

Cookie 模式不支持将生成的 STRM 上传到百度网盘，因此使用本地存储承接输出：

| 用途 | 配置 |
| --- | --- |
| 百度挂载 | `/baidu`，驱动 `BaiduNetdisk`，Cookie 模式 |
| 媒体扫描 | `/baidu/videos`，目录合并模式、自动深度 |
| STRM 输出 | `/baidu/strm`，嵌套挂载 `Local` 存储 |
| 本地输出根目录 | `/home/lee/openlist/data/baidu-strm` |
| STRM 镜像存储 | `/baidu-strm`，驱动 `Strm`，来源 `/baidu/strm` |
| 镜像根目录 | `/home/lee/ostrm/baidu-strm` |
| Emby 媒体库 | `百度网盘` |
| Emby 扫描目录 | `/home/lee/ostrm/baidu-strm/strm` |

`/baidu/strm` 是 OpenList 中的本地挂载，不是百度云端写入目录。媒体扫描仍只扫描 `/baidu/videos`。既有夸克和阿里云盘的扫描及输出设置不变。

扫描周期沿用全局 10 分钟设置。首次配置和新增资源由定时扫描发现，随后生成 STRM、本地镜像并调用 Emby 增量通知。`site_url` 使用局域网地址 `http://192.168.1.2:5244`。
