# 夸克与阿里云盘到 Emby 的 STRM 链路

本文记录当前部署中夸克网盘和阿里云盘从媒体扫描、生成 STRM、进入 Emby 到播放的配置和验证结果。两条链路已在 2026-11-19 的实际服务器环境中完成自动流程验证。

百度网盘的 Cookie 登录、302 播放与本地 STRM 输出配置见 [百度网盘接入说明](baidu-media-emby.md)。

## 当前状态

| 项目 | 夸克网盘 | 阿里云盘 |
| --- | --- | --- |
| OpenList 扫描路径 | `/quark/videos` | `/alipan/videos` |
| 合并模式 | 开启，自动深度 | 开启，深度 1，类型标签为电视剧 |
| STRM 输出 | `/quark/strm` | `/alipan/strm` |
| Emby 扫描目录 | 对应 STRM 输出的本地镜像目录 | 对应 STRM 输出的本地镜像目录 |
| 新增资源自动入库 | 已验证 | 已验证 |
| 播放验证 | HTTP Range 返回 206 | OpenList 返回 302 至阿里云盘 CDN，跟随后返回 206 |

本地镜像目录由部署环境配置，Emby 应扫描服务器上的本地目录，而不是 OpenList 的虚拟路径。STRM 中的视频地址使用可被播放设备访问的 OpenList 站点地址。

## 运行配置

- 媒体类型为视频，扫描路径分别为 `/quark/videos` 和 `/alipan/videos`。
- 开启扫描完成后自动生成 STRM。当前 OpenList 媒体扫描周期为 10 分钟；新增资源通常会在下一轮扫描后生成 STRM，并非上传事件触发的即时扫描。
- 夸克使用自动合并深度，阿里云盘使用深度 1，并将扫描路径标记为电视剧。每个扫描路径可以设置独立 STRM 输出目录；未覆盖的路径沿用全局 STRM 输出设置。
- STRM 模板为 `{site_url}/d{path}?sign={sign}`。`site_url` 必须是 Emby 所在服务器及播放设备都能访问的 OpenList 地址。局域网部署可使用局域网地址；外网播放需配置可达的公网域名、反向代理或 VPN 地址。
- 在「管理 → 媒体 → STRM」配置 Emby API 基础地址和管理员 API Key。基础地址填写到 `/emby`，例如 `http://<EMBY-LAN-ADDRESS>:8096/emby`。API Key 保存在 OpenList 私有设置中，界面以密码输入框显示，不应写入文档、日志或公开设置。
- Emby 全库扫描周期为 12 小时。新 STRM 写入本地镜像后，OpenList 会异步调用 Emby `POST /Library/Media/Updated` 通知新增路径，因此正常新增无需等待全库扫描，也无需手动刷新 Emby。

增量通知会合并短时间内的路径并批量提交；请求失败会有限重试。全库扫描保留为 Emby 的周期性兜底机制。

## 自动流程验证

在两个网盘的 `/videos/test` 目录分别上传 `001.mp4` 和 `002.mp4` 后，确认：

1. OpenList 自动扫描记录包含 `test/001.mp4` 和 `test/002.mp4`，并将其作为合并目录中的集数。
2. 两个本地 STRM 镜像目录均自动生成对应文件，内容中的 OpenList 地址可在局域网访问。
3. OpenList 日志和 Emby 日志确认新增 STRM 路径触发 Emby 增量刷新，Emby API 返回 HTTP 204。
4. Emby 按 STRM 本地路径收录对应条目；本次 `002.mp4` 均被识别为 Episode。
5. 对 STRM 地址发送 `Range: bytes=0-1023` 请求，夸克返回 HTTP 206；阿里云盘先返回 HTTP 302 至 CDN，跟随后返回 HTTP 206。

`test` 目录配置在合并视频扫描路径下，因此这些通用命名测试文件被识别为剧集是当前路径配置的预期结果。正式影视资源仍应使用匹配电影或电视剧库的目录与文件命名方式。既有内容抽查中，规范命名的剧集识别为 Episode，电影识别为 Movie。

## 已知边界

- 当前确认的夸克播放路径是 STRM 指向 OpenList `/d/...` 地址，测试响应为 HTTP 206，未观察到跳转到夸克 CDN 的 HTTP 302。因此夸克播放链路已可用，但“客户端直接获得夸克 CDN 地址”的 302 模式尚未实现或验证。
- 当前 STRM 地址使用局域网可达地址，只能保证同一局域网或可路由到该地址的设备播放。外网访问需另行配置可达地址及 TLS/反向代理或 VPN。
- 已验证当前账号、服务器和两轮测试资源的自动链路；尚未进行长时间稳定性、网盘令牌过期恢复、多网络环境和高并发压力测试。

本流程运行时在后端 v4.2.14、前端 v4.2.11 上通过验证。本说明随后端 v4.2.15 发布，不包含运行时代码改动；前端没有源码变更，因此继续使用 v4.2.11。后端正式包只构建 Linux amd64 标准包。
